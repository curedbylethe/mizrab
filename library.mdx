The library is what mizrab knows about the music on disk. It lives in `library/` as the Salam package `library` and produces one thing: a versioned JSON index of every audio file under the roots you scan, with the tags read from each file's head. The playlist reads that index at start, and `mizrab --scan` builds it headless. The scanner does not play, decode, watch the filesystem or look up metadata online.

## What a scan does

```sh
mizrab --scan ~/Music
```

The roots are the positional arguments after `--scan`, or `library.roots` from the config file when none is given (see [configuration](/configuration)). The scan walks every root, reads the tags of each audio file, merges the result with the index already on disk and writes the new index. It then prints one line and exits:

```text
mizrab: scanned 8 tracks: 8 added, 0 updated, 0 removed
```

A rescan is incremental. A file whose path, size and modification time all match the stored track is not read again and keeps its stored track, ID included. A file whose size or mtime differs is read again and counted as updated; a file with no stored track is added; a stored track whose file is gone is removed. The mtime is the true nanosecond value from `lstat`, so an edit that keeps the size is still noticed.

## The index

The index is a cache of filesystem state: it is always safe to delete, and a rescan rebuilds it.

- **Path.** `config.IndexFile`'s answer: `<data>/mizrab/index.json`, where `<data>` is `XDG_DATA_HOME` when set and absolute, else `~/.local/share`. `--index FILE` or `library.index` overrides it; the [configuration](/configuration) page covers the precedence. The data directory is deliberate: the playlist reads it at start, and playlists on disk will refer to its track IDs, so a cache cleaner should not be able to delete the index.
- **Format.** JSON, two-space indented, with `"schema": 1` first and the tracks after it, sorted by path. Each track's keys are the `Track` field names below, in that order. There are no timestamps, so scanning an unchanged tree twice writes the same bytes.
- **Atomic write.** The scan writes `index.json.tmp` and renames it over `index.json`, so a crash of the process never leaves a half-written index. Missing parent directories are created.
- **Recovery.** A file is discarded, and an empty index used in its place, when it is missing, cannot be read, is truncated (its length differs from its size on disk), declares a schema other than `1`, or does not decode strictly (an unknown key, a missing field, a wrong type or trailing data). The next scan then reads every file.

There is one schema version and no migration. A change of schema means a rescan, not an upgrade: an index of another version is simply discarded.

| Field | Meaning |
| --- | --- |
| `id` | First 16 hex characters of the SHA-256 of the absolute path |
| `path` | Absolute path, as the bytes the walk found |
| `title`, `artist`, `album`, `albumArtist`, `composer`, `genre` | Strings from the tags; `title` falls back to the filename stem |
| `year`, `track`, `trackTotal`, `disc` | Integers from the tags; 0 means absent |
| `durationMs` | Duration in milliseconds; 0 means unknown |
| `size`, `mtimeNs` | Size in bytes and modification time in nanoseconds since the epoch, from `lstat` |
| `tagged` | `true` when the tags gave a title, artist, album, year or track number; otherwise the tag fields stay empty and `title` is the filename stem |
| `format` | The lowercase extension without the dot |

## Scanning rules

- Roots are walked recursively. A root may itself be a symlink to a directory; the scan follows that one link.
- A file is indexed when its extension is `.mp3`, `.flac`, `.ogg`, `.oga` or `.wav`, in any letter case. `.opus` is not on the list because the decoder cannot open it.
- Names that start with `.` are skipped, files and directories alike. There is no other ignore list.
- Any symlink found inside a root is skipped, file or directory. A link cannot add a duplicate or form a cycle.
- Directories more than 32 levels below a root are not entered.
- A directory that cannot be listed is skipped silently; the walk carries on.
- Roots that overlap list a file once, compared by exact path.
- A root that is missing or is not a directory makes the scan fail without writing; so does a failed save. Every root is checked before the index is read, so a missing or unopenable root cannot prune it. An existing but empty root, such as a mount point with nothing mounted, still removes its tracks.

## Metadata

Each file is read up to its first 256 KiB through a small C shim: the whole file when it is shorter. From that head the scanner parses:

- ID3v2 for MP3;
- Vorbis comments for FLAC;
- Vorbis comments for Ogg, with a page assembler written for this package, because the standard library has no Ogg parser;
- the STREAMINFO block for FLAC, which gives `durationMs`.

A file with no usable tag is untagged: `tagged` is `false`. Whenever the tags give no title, `title` is the filename stem, so a title is never empty. An unreadable or empty file is still a track, untagged and with duration 0.

Limits:

- ID3v1 lives in the last 128 bytes of a file. A file that fits in the 256 KiB head has it read; a larger file never reaches it.
- Artwork, lyrics, comments, BPM and bitrate are not stored.
- `durationMs` is 0 for MP3, Ogg and WAV. Zero means unknown, never a guess.
- An Ogg comment packet over 64 KiB, for example one carrying embedded art, reads as untagged.
- A Vorbis `TRACKNUMBER=n/total` is parsed correctly for Ogg, but the standard library's FLAC path concatenates the digits, so a FLAC file written that way gets a wrong `track`. `TRACKNUMBER=n` with a separate `TRACKTOTAL` is read correctly.

## Limitations

- **No fsync.** Salam has none, so a power loss right after the rename can still lose the new file. The index is a cache and a rescan recovers it.
- **A rename changes the ID.** The ID is derived from the absolute path, so a renamed or moved file is a new track.
- **Two spellings are two tracks.** The standard library cannot resolve symlinks, so the same file reached through two root spellings, for example a symlinked root and its target, is indexed twice with two IDs.
- **Bytes are stored as read.** Paths and titles are never normalised: normalising a path can break `open()`, and normalising a title hides what the file says. Comparison is the reader's job, which is the rule "store bytes, compare normalised".

## Unicode

Paths and titles can hold any Unicode. The table records what the standard library reports for a fixed corpus; `tests/unicode_test.salam` asserts the four measured columns, and `tests/unicode_probe.salam` prints the table so you can re-measure. These are observations, not intentions. The fix for width belongs to basalam's width work, not to the scanner, and nothing here adds a width table.

Measured on Salam 0.5.9. The four columns after the text are measured. The last is the number of terminal columns the text occupies by Unicode East Asian Width (UAX #11); it is not computed by the probe, and where terminals disagree it says so.

| Text | Bytes | Codepoints | Graphemes | `term.Width` | Terminal columns |
| --- | --- | --- | --- | --- | --- |
| `界` | 3 | 1 | 1 | 1 | 2 |
| `音楽` | 6 | 2 | 2 | 2 | 4 |
| `한` | 3 | 1 | 1 | 1 | 2 |
| `é` (NFC) | 2 | 1 | 1 | 1 | 1 |
| `e` + U+0301 (NFD) | 3 | 2 | 1 | 2 | 1 |
| `🇮🇷` | 8 | 2 | 1 | 2 | varies, usually 2 |
| `👨‍👩‍👧‍👦` | 25 | 7 | 1 | 7 | varies, 2 where drawn as one glyph |
| `👍🏽` | 8 | 2 | 1 | 2 | varies, usually 2 |
| `لا` | 4 | 2 | 2 | 2 | varies, 1 or 2 |
| `नमस्ते` | 18 | 6 | 3 | 6 | varies |
| a lone combining acute | 2 | 1 | 1 | 1 | varies, 0 or 1 |
| `a` tab `b` | 3 | 3 | 3 | 3 | depends on the tab stop |

Two sources of error show up:

- **Width.** `term.Width` strips ANSI escapes and counts codepoints. There is no East Asian width table in the standard library, so CJK counts 1 instead of 2, a combining sequence counts once per codepoint, and a ZWJ family counts as its seven components. `term.Truncate` inherits the error: cutting four `界` to 3 returns three characters that occupy 6 columns.
- **Sort.** `str.Compare` is `strcmp`, so order is by UTF-8 bytes. `Z` sorts before `a` (`str.Compare("Z", "a")` is -1). The same visible word sorts differently by normalisation form: `café` in NFC compares greater than `café` in NFD (1), and `École` sorted with `Zebra` and `apple` lands last in NFC (index 2) but first in NFD (index 0).

## Command line

```sh
mizrab --scan ROOT... [--index FILE]
```

| Flag | Meaning |
| --- | --- |
| `--scan` | Scan the library roots given as arguments and write the index. No short form |
| `--index FILE` | Index file to read and write (default: `<data>/mizrab/index.json`). No short form |

| Exit code | Meaning |
| --- | --- |
| 0 | Success, including `--help` and `--version` |
| 1 | Runtime failure: the scan failed, printed as `mizrab: scan failed: <index path>`. A missing or non-directory root and a failed save both report this way, and the index is left as it was |
| 2 | Bad invocation: an unknown flag, or `--scan` with no root, which prints `mizrab: --scan needs at least one root` |

The success line is `mizrab: scanned <total> tracks: <added> added, <updated> updated, <removed> removed`. The `tests/run.sh` smoke checks run the real binary through a scan, a rerun that changes nothing, a missing root and a missing root argument; see [the test harness](/tests).
