mizrab is one Salam program plus the audio engine and the vendored C it drives, a test corpus, and the files for this documentation site, all at the repository root.

| Path | Contents |
| --- | --- |
| `main.salam` | Entry point: flag parsing, `--version`, `--help`, `--scan` with `--index`, `--config`, the usage block, and the app shell when stdin is a terminal |
| `commands/` | Command layer: the version constant and the usage string |
| `audio/` | Vendored miniaudio and stb_vorbis plus the decode/ring/device engine: `miniaudio.h`, `stb_vorbis.c` and the `miniaudio.c` implementation unit that includes both; the C glue `ma_shim.{h,c}`; and the Salam package `audio` (`audio.salam` entry file, `decoder.salam`, `ring.salam`, `metrics.salam`, `device.salam`). See [the audio engine](/audio-engine) |
| `player/` | The playback controller on top of the engine: the Salam package `player` (`player.salam` entry file, `state.salam`, `errors.salam`, `controller.salam`, `queue.salam`): the state machine, the queue and the controller. See [the playback controller](/playback-controller) |
| `library/` | The library scanner: the Salam package `library` (`library.salam` entry file, `walk.salam`, `track.salam`, `ogg.salam`, `index.salam`, `scan.salam`) and the C shim `library_shim.{h,c}` that does `lstat` and the binary head read. See [the library](/library) |
| `config/` | Where mizrab keeps its files: the Salam package `config` (`config.salam` entry file and its XDG directory resolver, `settings.salam` with the INI-subset reader, `Settings`, `Resolve` and `Describe`) and `config.sample.ini`, the commented sample a test loads. See [configuration](/configuration) |
| `ui/` | The terminal interface: the Salam package `ui` (`ui.salam` entry file, `keymap.salam` with `Command` and `Vim`, `shell.salam` with the screen and its tree, `loop.salam` with the event loop, `playlist.salam` and `now_playing.salam` with the two body panels, `status.salam` and `mode.salam` with the footer segments and the prompt, `command.salam` with the command parser and its completions, `overlay.salam` with the help and quit modals, `library_view.salam` with the rows, filter and cursor, `text.salam` with the one truncation rule, `terminal.salam` with the restore sequence and signal guard, `instance.salam` with the single-instance lock). See [the app shell](/app-shell) |
| `tests/` | The `*_test.salam` programs with their `.out` goldens (`cli`, `ring`, `decode`, `engine`, `state`, `player`, `queue`, `library_shim`, `walk`, `tags`, `ogg`, `index`, `rescan`, `paths`, `config`, `keymap`, `shell`, `loop`, `terminal`, `instance`, `unicode`, `library_view`, `frames`, `playlist`, `now_playing`, `prompt`, `command`, `overlay`, `frame_budget`), the `run.sh` harness, the `soak.salam` / `soak.sh` pair behind `make soak`, the `gap.salam` / `gap.sh` pair that measures the inter-track gap by hand, the `shell-measure.sh` and `frame-measure.sh` pty harnesses with their `probe/` programs, `unicode_probe.salam`, which prints the table `unicode_test` asserts, and `fixtures/`, the audio files with their provenance: one small tone per decoder format plus the tagged and packet-split files the scanner tests read |

The binary reads `config/` at startup: it resolves the four directories and loads `config.ini` when one exists. `ui/` is the interface the binary includes: the keymap, the shell tree, the two body panels, the footer segments and the prompt, the command parser, the two overlays, the library view, the truncation rule, the event loop, the terminal guard and the instance lock.

Playback is split across two directories. `audio/` is the substrate: decoding, the ring buffer and the device. `player/` sits above it: the playback state machine, the commands and the queue. The binary includes both, through `ui/`'s event loop.

The CI legs run the engine test on miniaudio's null backend as part of `make test`, so they need neither a sound card nor an ALSA configuration. `make soak` is not run in CI.

The documentation site lives at the repository root, not in a `docs/` directory: Mintlify resolves page paths against the directory that holds `docs.json`, so a page at `docs/index` would serve `/docs/...` and leave the site root empty.

`build/` and `.salam-build/` appear after a build and are ignored by git. `make clean` removes both.
