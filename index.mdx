mizrab is a music player built on basalam: a terminal application written in the [Salam](https://github.com/SalamLang/Salam) programming language.

> **Status: audio engine and playback controller, no player yet.** The [audio engine](/audio-engine) exists: it decodes MP3, FLAC, WAV and OGG, streams them through a lock-free ring buffer to miniaudio's playback callback, and runs headless on miniaudio's null backend, where its tests exercise it. The [playback controller](/playback-controller) above it exists too, tested the same way. The binary uses neither yet: it answers `--version` and `--help` and prints its usage when invoked bare. There is no playback command, no library scanning and no user interface; the first playable build arrives when the command line gains a play command.

The playback controller owns the state machine and the queue. The [audio engine](/audio-engine) page and the [playback controller](/playback-controller) page are the two findings for playback.

Build it with [install](/install), then see the [make targets](/make-targets), the [test harness](/tests) and the [repository layout](/repository-layout). To work on mizrab, read [contributing](/contributing); the source, issues and releases live on [GitHub](https://github.com/curedbylethe/mizrab).

## Built on

- [**basalam**](https://github.com/curedbylethe/basalam) — a retained-mode terminal UI library for Salam. It is vendored at `vendor/basalam` and pinned to the commit the `v0.2.0` release tag points at.
- [**Salam**](https://github.com/SalamLang/Salam) — the language, compiler and standard library mizrab is written in.

The player binary currently imports only the Salam standard library (`flag`, `os`) plus its own `commands` package; the basalam include arrives with the application layer. The audio engine additionally uses `atomic`, `mem`, `sync` and `thread`, and is exercised by the tests, not by the binary. The `player` package is tested headlessly and is not yet included by the binary.
