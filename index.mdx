mizrab is a music player built on basalam: a terminal application written in the [Salam](https://github.com/SalamLang/Salam) programming language.

> **Status: audio engine, playback controller and library scanner, no player yet.** The [audio engine](/audio-engine) exists: it decodes MP3, FLAC, WAV and OGG, streams them through a lock-free ring buffer to miniaudio's playback callback, and runs headless on miniaudio's null backend, where its tests exercise it. The [playback controller](/playback-controller) above it exists too, tested the same way. The binary uses neither yet. It does run the [library scanner](/library): `mizrab --scan ROOT...` walks the roots, reads tags and writes a JSON index. Otherwise it answers `--version` and `--help` and prints its usage when invoked bare. There is no playback command and no user interface; the first playable build arrives when the command line gains a play command.

The playback controller owns the state machine and the queue. The [audio engine](/audio-engine) page and the [playback controller](/playback-controller) page are the two findings for playback; the [library](/library) page covers the scanner and its index.

Build it with [install](/install), then see the [make targets](/make-targets), the [test harness](/tests) and the [repository layout](/repository-layout). To work on mizrab, read [contributing](/contributing); the source, issues and releases live on [GitHub](https://github.com/curedbylethe/mizrab).

## Built on

- [**basalam**](https://github.com/curedbylethe/basalam) — a retained-mode terminal UI library for Salam. It comes from Salam's package registry at `v0.3.1`, pinned in `salam.lock`.
- [**Salam**](https://github.com/SalamLang/Salam) — the language, compiler and standard library mizrab is written in.

The player binary currently imports the Salam standard library (`conv`, `flag`, `os`) plus its own `commands` and `library` packages, and links the third C object, `build/library_shim.o`; the basalam import arrives with the application layer. The `library` package additionally uses the `audio.tag` and `audio.flac` readers pinned in `salam.toml`, plus the standard library's JSON, crypto and filesystem packages. The audio engine uses `atomic`, `mem`, `sync` and `thread`, and is exercised by the tests, not by the binary. The `player` package is tested headlessly and is not yet included by the binary.
