mizrab is built from source; there is no separate installer. You need the pinned Salam compiler, a C toolchain with LLVM, and network access on the first build, which downloads the locked packages.

## Prerequisites

- **Salam 0.5.9.** The pinned compiler version lives in `.salam-version`, and `salam version` must report exactly that. Build or install it from the [Salam repository](https://github.com/SalamLang/Salam).
- **A C toolchain with LLVM.** Salam's LLVM backend uses `clang` and the system linker. On Debian/Ubuntu install `build-essential` and `clang`; on macOS install the Xcode command-line tools with `xcode-select --install`.
- **macOS or Linux.**

## Clone

```sh
git clone https://github.com/curedbylethe/mizrab
cd mizrab
```

The first `make build` runs `salam deps`, which downloads the packages `salam.lock` pins and checks their sha256 sums. That needs network access once. If you are moving to a newer pin, `make deps` re-runs it on its own.

## Build and run

```sh
make build
make run
```

`make build` first runs `salam deps`, which fetches the locked packages, then compiles the vendored miniaudio, its C glue and the library's C shim into `build/` with `cc`, then compiles `main.salam` to `build/mizrab` with `--backend=llvm` and links the three objects in; `make run` builds and then runs the binary. At this commit that binary opens the [app shell](/app-shell) when stdin is a terminal: `space` plays and pauses, `n` and `p` move the queue, `j`/`k` and `Enter` move and play a playlist row, `/` filters the list, `:` opens the command line, and `q` quits, asking first while a track plays; `h`/`j`/`k`/`l`, `Tab` and the arrows move the focus. With stdin not a terminal the same binary prints its usage block and exits 0, so a pipe or a script sees the block. `./build/mizrab --scan ROOT...` scans a music library and writes its [index](/library). Run `make help` for the short target list, and see [make targets](/make-targets) for the full reference.

## Use a compiler off `PATH`

`SALAM` overrides the compiler the Makefile invokes, for a Salam build that is not on your `PATH`:

```sh
SALAM=/path/to/salam make build
```

## macOS deployment target

On macOS the Makefile pins `MACOSX_DEPLOYMENT_TARGET` to the running OS version so the linker does not warn about a mismatched SDK. Leave it alone; if you need a different value, export your own before running `make`.
